# 市场日报：两个版本，两份规范

市场日报出**两份内容不同**的产物，不要互相套用：

| | 文字版 | 图片版 |
|---|---|---|
| 路径 | `market_reports/YYYY-MM-DD.md` | `market_reports/YYYY-MM-DD-image.md` + `.png` |
| 内容 | **完整数据 + 完整推理链** | **文字精炼 + 图表** |
| 图表 | 不带（md 源码阅读，图反而碍事） | 必带（折线图 / K 线图） |
| 用途 | 留档、细读、回查 | 分享、快速阅读 |

**为什么必须重写而不是截取**：`market/analyze.py:render()` 那种逐行拼接的紧凑文本，
配合渲染器的 `nl2br`，相邻两行会被粘进同一个 `<p>`，成一块没有呼吸感的文字墙。
实测：

```
输入：  活跃市值 166,792（09-15）
        走势：09-14 -1.42　09-15 -1.83

输出：  <p>活跃市值 166,792（09-15）<br />走势：09-14 -1.42　09-15 -1.83</p>
```

本文规定的是**图片版**；文字版按「完整、可细读」自由组织，无排版约束。

## 版面约束（实测值，改之前先读）

| 项 | 值 | 来源 |
|---|---|---|
| 输出图宽度 | **1200 px** | Playwright viewport 600 × device_scale_factor 2 |
| 实际内容宽度 | **560 CSS px** | 600 减去 body 的 `padding: 20px` 左右共 40 |
| 模板的 `max-width: 680px` | **不起作用** | viewport 只有 600，body 先被卡住了 |

560px 的含义：**表格最多 4 列**，每列净可用不到 100px。

## 结构

```
# 市场环境日报　2026-09-15

**空头区间　仓位上限 1~2 成　三层同向指向防守**

## 一、市场闸门        （活跃市值 K 线 + 读数表 + 指数表）
## 二、指数点评        （挑重点指数，走势/成交量/形态）
## 三、上证指数形态    （K 线图 + 形态/量能/位置三段简评）
## 四、情绪与资金      （涨停折线 + 新高折线 + 术语解释）
## 五、热点结构        （主线/支线/超跌）
## 六、关键洞察
## 七、操作含义与失效条件
```

章节序号用中文数字。**章节之间不用横向分割线**——靠标题的上下间距分隔就够了。

## 硬性规则

每条都附了成因——**成因不成立时规则才可以改**，不要当教条照搬也不要随手删。

### 1. 标题、表格、列表、引用块的前后各留一个空行

**成因**：`nl2br` 会把单换行变成 `<br>`，不留空行相邻两行会粘进同一个 `<p>`。
`markdown_lab.py:preprocess_markdown()` 只对「`**加粗行**` 或 `##标题` 紧跟列表」
这一种情况自动补空行，其余一概不管。

### 2. 不要用横向分割线

不写 `---`。模板的 CSS 会给每个 `<hr>` 画一条横线，把连续的阅读流切断。

**注意**：模板里 `h1` 自带 `border-bottom`，那是标题下划线、不是分节线——它**去不掉也
不用管**，只要不额外加 `---` 就行。

### 3. 表格不超过 4 列

**成因**：内容区 560px。5 列时每列约 90px，中文标签会折成两行，反而更难读。

### 4. 长数据拆成多行表格，不要挤在一行

12 只指数距 60 线的正确写法是 3 列表格分 12 行。挤成一行会折成 4 行且难以对齐。

### 5. 涨跌数字用 `.up` / `.down` 上色（红涨绿跌）

```html
<span class="up">+1.55%</span>      <!-- 红涨 -->
<span class="down">-1.83%</span>    <!-- 绿跌 -->
```

**不要用 `.positive` / `.negative`** —— 那两个类表达的是语义上的「好/坏」（橄榄绿/陶土红），
个股分析报告在用，与价格方向不是一回事。**涨跌必须红涨绿跌**（A 股惯例）。

**成因**：`md_in_html` 扩展开着，原始 HTML 会透传；这三个类都在模板里定义好了，
不改 CSS 就能用。涨跌数字满屏都是，上色后扫读快很多。只给**数字**上色，不要整行变色。

### 6. 不使用 emoji

**成因**：这是每天的决策材料，不是营销图。用户明确要求严肃。h1 也不带。

### 7. 每章结尾一条 `>` 引用块作小结

**成因**：读者对「每章末尾有一句人话结论」形成预期后，可以只扫引用块快速过一遍。
引用块内容用**口语化的一句话**，不要复述上面的数字。

### 8. 章节顺序：闸门优先

市场闸门必须在最前。**成因**：它回答「要不要参与」，其余章节回答「参与什么」。

### 9. 闸门缺数据必须显式写出，不得省略该章

即使 0AMV 数据缺失，也要保留「一、市场闸门」并写明 `> 活跃市值数据不可用…`。

**成因**：`analyze.py:414` 的纪律——「没看到闸门警告」会被误读成「可以参与」。
这与个股报告「没新闻就略过第 2 章」的做法**相反**，别照搬那边。

## 配图

### 出图

图由脚本生成，不由 AI 画：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.charts 20260915
```

四张图落在 `market_reports/charts/YYYY-MM-DD/`：`limitup.png`（涨停家数折线）、
`newhigh.png`（创 20 日新高双线）、`amv.png`（活跃市值 K 线）、`shindex.png`（上证 K 线）。

### 嵌入语法

用**仓库相对路径** + `<img>` 标签：

```html
<img src="market_reports/charts/2026-09-15/amv.png" style="width:100%; margin:1rem auto" />
```

**成因**：`convert_local_images_to_base64` 对相对路径按 **cwd** 判断存在性，只要渲染时
cwd 是仓库根就成立（skill 的命令本来就在仓库根跑）。相对路径让 md 可移植、git diff
干净；绝对 `file://` URI 会把用户家目录路径写进 git 跟踪的文件。

不要用 `![]()` 语法——它没法控宽度，1800px 宽的原图会被压得很难看。

### 静默失败陷阱（必读）

**找不到图，渲染器只 print 一句警告就继续**，最终 PNG 里是坏图占位。项目里
`output/中远海能(600026)_分析报告.png` 就是这么坏掉的，而且一直没人发现。

所以：

- `market.charts` 落盘后自带 `assert p.is_file()`
- **渲染完必须自己 Read 一遍图**，确认图表真的显示了，不要只看日志说「已生成」

## 内容要求

### 术语解释

炸板率、晋级率、基差这类名词**要给解释**，但不要打断正文——集中放在首次出现的章节
末尾（`### 三个术语`），每个两三句话，说清**怎么算**和**怎么读**。

### 宽基指数要点评，不是罗列

不要只给一张涨跌表。挑 3-4 只重点讲：当日最强/最弱的、距 60 线最远/最近的，
各自说清**走势、成交量、形态**。其余用表格带过。

### 上证指数形态独立成节

用户明确要求。三段：**形态**（趋势结构、关键均线位置）、**量能**（反弹/横盘期的量能
变化意味着什么）、**位置**（关键位在哪、距离多少）。

### 不要引用规则出处

报告里**不出现**「《某某》说」「某某文档的判据」「参考某某材料」这类引用。
判断要**自圆其说**，靠数据与推理本身站住，不靠权威背书。

```
✗  依据是《十分钟讲透》里 2020-06-01 那个案例，文章判定信号无效
✓  若用大盘 60 线，2020-06-01 那天上证已在自身 60 线上方，信号应当立即生效，
   但实际行情是又横盘许久才启动——只有用 0AMV 自身的 60 线才解释得通
```

**成因**：这是给自己看的决策材料，规则从哪来不重要，**规则怎么用、为什么在这里成立**
才重要。引用出处还把外部文档的存在暴露给了可能的转发对象。

（技能与规范文档里可以正常标注出处——那是写给维护者看的，不受此限。）

## 不沿用的两处

| 个股报告有 | 图版市场报告 | 理由 |
|---|---|---|
| h1 带 emoji | 不带 | 用户要求严肃 |
| 结尾免责声明 + 出品方 | 不写 | 那是给外部读者的；这是个人复盘材料 |

## 写完自检

1. 全文搜一遍，确认**零 emoji**、**零 `---`**
2. 每张表数一遍列数，≤4
3. 每个 `##`、表格、列表、`>` 前后都有空行
4. 涨跌数字都包了 `.up` / `.down`（不是 `.positive` / `.negative`）
5. 每个 `##` 章节末尾都有 `>`
6. 闸门章节在第一节，且没有被省略
7. **图片路径都是仓库相对路径**，且对应文件真实存在
8. 渲染后**自己 Read 一遍图**确认图表显示了
