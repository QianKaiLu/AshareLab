## 高：日更的 akshare 兜底仍是 3 线程，走新浪时有崩溃风险

2026-09-17 发现：akshare 的新浪行情接口内部用 py_mini_racer（V8）算复权因子，
而 **V8 实例不是线程安全的**——并发调用会 FATAL 掉整个进程。实测 3 线程跑 200 只
必崩，栈顶是 `address_pool_manager.cc(67) Check failed: !pool->IsInitialized()`。

重建流程已改成 4 进程（`datas/fetch_all_market.fetch_full_history_parallel`），
但**日更的兜底路径没改**：`fetch_stock_bars_parallel` 仍是 `ThreadPoolExecutor(3)`，
而 `fetch_daily_bar_from_akshare` 在东财熔断后会转 `fetch_daily_bar_from_sina`。
东财现在整体不可用，等于每次兜底都在踩这个坑。

目前没炸是因为兜底量小（2026-09-17 是 0 只），一旦某天有几十上百只需要兜底就有风险。

**修法**：兜底轮改用多进程；或退一步——单线程串行（兜底量小，慢一点可接受）。
注意多进程要求入口有 `if __name__ == "__main__"` 保护，而 `workflow/daily_update.py`
是 `sys.exit(run())` 脚本式，改造时要一并处理。

## 中：数据源的能力边界（2026-09-17 实测，省得重测）

全库重建时逐项测过，这些是硬约束不是临时故障：

| 源 | 能拿完整历史？ | 备注 |
|---|---|---|
| 新浪 `stock_zh_a_daily` | **能** | 乘法式、恒正，重建主源；**不支持北交所** |
| baostock | 能 | 更权威；但**串行 4.51s/只**（全量 6.6 小时），多进程被服务端拒（Broken pipe） |
| 腾讯 `fqkline` | **不能** | 个股硬上限约 **641 根**（约 2.5 年）；指数 2000 根。支持 qfq（`qfqday` 字段） |
| 网易 chddata | **已失效** | 只返回 6 行 |

最新一根完全相同。旧说法「baostock 与新浪的因子不同，整段覆盖会平移价格水平」不成立
——那 0.1% 更像两位小数的舍入。

**北交所（92xxxx）新浪与 baostock 都取不到**，只能靠 tushare。

## 中：非正价闸门仍是「整只拒绝」，脏行形态没覆盖全就会丢股票

2026-09-17 重建时，3 只科创板（688089 / 688143 / 688173）各带一行**占位数据**
（2024-11-06，开/高/低全为 0、volume=0、close 保留前收），触发「1 行非正价 →
整只拒写」，三只从库里凭空消失。**而且当时的失败统计只记「抓取失败」，不看写库结果**，
所以日志报「首轮失败 0 只」，实际少了 3 只。

已做两处修补：

1. 写库前先丢弃「开/高/低全 0 且无成交且 close>0」的行（与 baostock 默认丢弃停牌日
   同一原则），且加了 `close>0` 条件，确保不会误伤真正的复权污染行
2. `save_daily_bars_to_database` 改为返回写入行数，上层据此把「抓到了但没入库」
   计入 failed

**但闸门本身还是「整只拒绝」**：只要再出现没被预过滤覆盖的脏行形态，就会重演
「股票凭空消失」。建议改成「非正价行占比超过阈值才拒绝整只，个别行丢弃并告警」。

## 低：多源复权口径的一致性检查

重建后全库来自单一源（新浪乘法式），历史上混进来的东财减法式已不存在。
但**这个保证只对「不再引入第二个源」成立**——将来若加了新源或改了兜底路径，
同样的污染可以再次悄无声息地发生（见下方已解决条目）。

建议在 `save_daily_bars_to_database` 里加一条「与库中已有重叠区间比对」的检查，
口径不一致时告警而不是静默覆盖。

## 已解决（2026-09-17）

### 000708 的负价与「静默换口径」—— 全库重建根治

原问题：`fetch_daily_bar_from_akshare` 优先东财，而东财 qfq 是**减法式**
（原价 − 累计分红），分红累计超过早期股价时整段历史变负。000708 累计分红 8.74 元
> 2005 年股价 5.23 元，2005~2018 整段被压成负数并 UPSERT 覆盖旧数据。

触发路径当天已修（commit `2963e6b`：写入前加非正价闸门、除权兜底改走新浪、
tushare 补锚点校验），**存量数据由当天晚上的全库重建一并修正**：全库统一成新浪
乘法式口径（基准日 = 当天），000708 的 2008-01-02 收盘从错误的 3.14 回到 5.53，
而未受污染的股票（000001、600026 抽查 2008/2015/2026 三个时点）与旧库差异均为 0.00%。

重建耗时 14 分 44 秒，产出 15,135,346 行 / 5561 只，与旧库总量完全一致。
细节见 `workflow/rebuild_database.py` 的 docstring 与 qk-stock-daily-update 技能场景 7。
