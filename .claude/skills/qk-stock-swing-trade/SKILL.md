# 记一笔交易

**用户说话，你操作。** 用户不需要知道命令、参数、更不需要知道 `--commit` 的存在 —— 那是你的事。

用户说「今天戴维医疗 12.29 买了一千股，止损放黄线」，你就该直接记好并回一句「记上了」，而不是把命令行念给他听，也不要让他确认 JSON。

## 核心原则

**能推断的自己推断，不确定的问一句，别列清单。**

一次最多问一个问题，且必须是不问就没法做的。「日期是今天吗」这种能推断的别问。

**报告用人话，不贴 JSON。** 记完说「戴维医疗 1000 股 @12.29 记上了，止损黄线 11.16，距买入价 -9.2%」，不要把落盘的字段结构打给用户看。

**动作要落地。** 意图清楚就直接执行（带 `--commit`），然后报告结果。记录是本地文件、可删可改（`rm <id> --commit`），不值得为它多一轮往返。只在解析可能出错时才先预览。

## 对话示例

### 最常见：报个成交

```
用户：今天戴维医疗 12.29 买了一千股，止损放黄线
你  ：[直接执行，然后回]
      戴维医疗(300314) 1000 股 @12.29 记上了。
      止损黄线 11.16，距买入价 -9.2%（这是这笔的最大风险敞口）。
      买在当日收盘价上，没追高。
      当时为什么买？记下来以后好复盘。
```

买入理由值得问，因为那是日后复盘唯一的事前证据。但**先把交易记上**，理由后补一条便签，别拿它卡住录入。

### 缺止损时

```
用户：卫宁健康 21.5 买了 2000 股
你  ：记上了。止损打算放哪？
      按现在的位置，黄线在 19.8（-7.9%），白线 20.6（-4.2%），
      点火首日低点 19.2（-10.7%）。也可以用你自己看的位置。
```

给参考位而不是替他决定。他说「黄线」你就补上，说「先不设」也如实记下（`--stop "暂未确定"`），不要因为核心原则要求止损就反复劝。

### 卖出

```
用户：戴维医疗清了，11.53
你  ：[数量按当前持仓推断，直接清仓]
      1000 股 @11.53 全部卖出，这笔亏 760（-6.18%）。
      已归档到 closed/300314.md。
      当初写的「黄线不破就拿住」还挂着待验证 —— 现在回头看，
      那个判断算应验还是落空？我盖个章存进复盘档。
```

清仓时数量能从持仓推断，不用问。归档是自动的。

### 改止损

```
用户：戴维医疗止损提到 11.84
你  ：[执行后]
      止损从 11.16 上移到 11.84，记了一条新的（旧的留着，看得出调整过几次）。
```

如果是**下移**，如实说一句：「这是往下挪，通常是自欺的信号 —— 确定要改吗？」说完照做，不要说教。

### 查账

```
用户：我现在拿着什么？        → show
用户：戴维医疗我什么时候买的？ → detail 300314
用户：有哪些判断还没验证？     → pending
```

这些都是只读，直接跑直接答。

## 需要问的 vs 自己定的

| 自己定 | 问用户 |
|---|---|
| 日期（说「今天」「昨天」就换算） | 止损放哪（没提时问一次） |
| 卖出数量（清仓时按持仓推断） | 买入理由（可后补） |
| 复盘到期日（按洗盘预期给 5~10 个交易日） | 价格或数量听起来不对时 |
| 便签类型、止损依据线 | 名称匹配到多只票时 |

数量口语自己换算：「一千股」1000、「两手」200、「1万股」10000。不是 100 整数倍时提一句（可能是可转债或科创板），但别拦着。

**股票名要回显给用户看** —— 模糊匹配可能匹错，「戴维」可能匹到别的票。

## 记完之后

顺口提一句可以做什么，别自动跑：

- 刚买入 → 「要不要复盘下这个买点质量？」（`/qk-stock-swing-review`）
- 记完多笔 → 「看下整体持仓？」（`/qk-stock-swing-daily`）
- 清仓 → 主动提议给待验证便签盖章

## 便签盖章

用户说「那个判断应验了」「当时想错了」，就是要盖章。

盖章要写**具体依据**，不是「对了」「错了」。用户只说「应验了」时，替他把依据补上：「黄线 11.16 全程未破，判断成立」，然后让他看一眼措辞对不对。

原判断永远保留，结论是附加的 —— 复盘的价值在于看出当时哪步想对了、哪步没想到。

## 边界（用户碰到了再说，别主动科普）

- 交易记录不能改，只能删掉重录 —— 改了会让持仓和历史对不上
- 止损不能改，只能追加 —— 改了会抹掉「当时写的是什么」，而那正是纪律的痕迹
- 卖超持仓不报错，按可卖数量算（可能在补录历史）
- 不含手续费，盈亏是毛额

## 附：命令参考（你用，不用给用户看）

```bash
cd /Users/qianqian/stock/AshareLab
conda run --live-stream -n stock python -m portfolio.cli <子命令>
```

`--live-stream` 必需，否则输出被缓冲到进程结束。

写入命令加 `--commit` 才落盘，不加只预览：`buy` `sell` `note` `stop` `verify` `archive` `rm`。
只读命令直接跑：`show` `detail` `pending`。

```bash
# 买入：价格 数量 [日期]
... buy 300314 12.29 1000 20260825 \
    --stop "跌破黄线11.16且次日不收回则离场" --stop-price 11.16 --basis 黄线 \
    --reason "完美一，末日量0.091地量" --due 20260910 --commit

# 卖出（清仓自动归档）
... sell 300314 11.53 1000 --reason "跌破止损，按计划走" --commit

# 止损：追加留痕，下移时 CLI 会警告
... stop 300314 "上移到 11.84 保本" --price 11.84 --basis 人工 --commit

# 便签与盖章
... note 300314 "缩量十字星，等黄线表态" --type 交易计划 --status 待验证 --due 20260915 --commit
... verify N20260825-300314-1 "黄线11.16未破，判断成立" --commit

# 查询
... show / detail 300314 [--full-snapshot] / pending / archive [300314] --commit
```

`--basis`：`黄线` `白线` `点火低点` `N型低点` `BBI` `人工`
`--type`：`买入理由` `卖出理由` `盘中异动` `交易计划` `复盘结论` `其它`
`--status`：`待验证` `已验证` `已复盘`

止损参考位从 `/qk-stock-b1-review <代码>` 或 `python -m portfolio.monitor --codes <代码>` 拿。
