# 当日市场分析

把**客观数据**与**定性研判**合成一份「今天是什么环境、该做什么」的报告。

分两层，**不要混为一谈**：

- **客观层** —— `market.cli report` 的输出，各层的测量值与规则判定
- **研判层** —— 你把客观层综合成关键洞察。**这是本 skill 存在的理由**：客观层自己就能跑，缺的是「所以呢」

客观层有意不下结论。`market/analyze.py` 的 docstring 写着：「只做客观聚合与规则判定，
不下『主线就是 XX』的结论——那属于研究假设层，由人/AI 结合盘面与消息面研判。」
这句话划的就是本 skill 的职责边界。

## 运行环境（必读）

- conda `stock` 环境 + `PYTHONPATH=.` + `--live-stream`，三者缺一不可
  （缺 `--live-stream` 会缓冲输出到进程结束，看起来像卡死）
- 全部命令在项目根 `/Users/qianqian/stock/AshareLab` 下执行

## 步骤 1：确保当日快照存在

报告读的是 `market/history/YYYYMMDD.json`。先确认今天有没有：

```bash
ls market/history/$(date +%Y%m%d).json 2>/dev/null || echo "缺快照"
```

缺了就抓（约 30 秒）：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.cli snapshot
```

**快照必须当天抓。** 实时接口（乐咕活跃度、东财板块榜、同花顺/新浪行业）没有历史参数，
补抓会把今天的数据存成历史日期、污染环比。所以历史日期只能补到涨停池那几项，
`market.cli backfill` 就是干这个的——但补不出完整的当日快照。

## 步骤 2：跑报告

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.cli report
```

约 10 秒，输出八段：

| 段 | 内容 |
|---|---|
| **L0 活跃市值** | 区间（多头/空头/变盘窗口/纠结）、距 60 线、60 线斜率、MACD、**仓位上限** |
| **L0 指数** | 12 只宽基（含证券公司）的当日涨跌、距各自 60 线、大小盘风格、**券商+沪深300+创业板共振** |
| L1 情绪周期 | 五段状态机：涨停数/晋级率/炸板率/昨日涨停溢价 |
| L2 资金风向 | 沪深300 vs 中证2000 创 20 日新高占比、**期指基差**、**沪深300ETF 放量** |
| L2 超跌板块 | KDJ 为负的行业，**按超卖深度排序** |
| L4 主线判定 | 有无主线、支线及所缺条件 |
| L3 连板梯队 | 5板/4板/3板/2板分布与封单 |
| L3 涨停行业分布 | 当日涨停的行业归属与前排个股 |
| L3 题材延续性 | 近 5 日进前 6 的次数 |
| L3 板块涨幅榜 | 概念 + 行业两套口径交叉验证 |

**L0 两段是前置闸门，其余是「参与什么」。** 读报告时先看 L0，它决定后面所有内容的
操作含义。

想单独看某一层，可以绕过报告直接跑：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.amv [YYYYMMDD]      # 活跃市值
PYTHONPATH=. conda run --live-stream -n stock python -m market.index [YYYYMMDD]    # 指数 + 共振
PYTHONPATH=. conda run --live-stream -n stock python -m market.sector [YYYYMMDD]   # 超跌板块
PYTHONPATH=. conda run --live-stream -n stock python -m market.table --days 30     # 每日观察数据表
```

`market.table` 是那张「每天维护的表」（`日期 / 活跃市值 / 涨停 / 沪深300创新高 / 中证2000创新高`），
用户要「看最近一段的走势对比」时直接给它。**它会自己标出「区间内哪些交易日没有快照」** ——
快照是手动触发的，缺的日子容易被误读成休市，补法是 `market.cli backfill --days N`。

### 几个必须转达的口径

- **ETF 日线可能滞后一天**（新浪该接口当天常还没出），输出里带 `⚠ 只到 YYYY-MM-DD` 要原样转达
- **期指基差跨换月日不能做环比** —— 当月合约交割日收敛到 0、换月后立刻转负是期限结构，
  实测 IF 从 -4.10 跳到 -36.73
- **超跌板块在普跌行情里没有区分度** —— 实测 2026-09-15 有 68/90 个行业 KDJ 为负，
  这时看排序（J 越负越超跌）而不是看是否在榜
- **中证2000 创新高的分母只有 699 而不是 2000**（库里缺北交所小票），是占比参照不是绝对家数

## 步骤 3：关键洞察（你做）

客观层给数据，这一层给判断。按五段组织：

### 一句话总览

今天是什么环境，一句话说清。例：「活跃市值空头 + 11 只宽基全在 60 日线下 + 情绪退潮
——三层同向，防守。」

### 层间一致性 / 矛盾

**这是关键洞察最重要的部分，也是只有你能给的部分。** 各层很少完全同向，
**矛盾处才是信息**：

- **指数横盘但活跃市值失血** → 钱在撤、价还撑着，最危险的一种。2026 年 8 月就是
  这个形态：上证微涨而 0AMV 跌 10.78%
- **活跃市值空头但情绪高涨** → 普跌里的局部抱团，参与要极轻
- **指数全部跌破 60 线 + 活跃市值空头 + 情绪退潮** → 三层同向，没有分歧，别找理由
- **活跃市值多头但指数在 60 线下** → 资金先动、价格没跟上，是观察窗口

### 关键变化

与昨日 / 近 5 日比，**变了什么**。用数字不用形容词：
「60 线斜率由 -2.49% 转为 -3.06%，在下行加速」比「继续走弱」有用得多。

### 操作含义

- **仓位上限**（直接引用活跃市值层的判定，不要自己改）
- 能做什么 / 不能做什么
- 有持仓时，环境对持仓的含义

### 失效条件

什么情况下这个判断会变，**必须给出来**，否则判断无法被证伪。例：
「活跃市值站上自身 60 日线且 MACD 白线上水」。

## 输出组织

```
一句话总览（环境定性 + 一句话依据）
        ↓
## 关键洞察        矛盾与一致、关键变化（研判，带数字）
        ↓
## 操作含义        仓位上限、能做什么不能做什么、对持仓的含义
        ↓
## 市场数据        客观层原文（L0 两段在前，L1-L4 随后）
        ↓
## 需人工确认      数据滞后、视野外的因素
```

**客观层原样引用，不要改写口径**；研判另起一段写明是你的判断。两者混成一句会让
用户分不清哪是测量、哪是推断。

## 纪律

- **不做收益预测**。可以说环境强弱、条件是否成立，不说「预计涨 X%」
- **层间矛盾必须摊开讲**，不要选一边悄悄忽略另一边
- **数据滞后要转达**：0AMV 靠手工录入，输出里的 `⚠ 0AMV 数据落后 N 个交易日` 原样带出来，
  并说明下面的判定基于落后数据
- **视野外的直说**：政策、消息面、减持解禁、外围市场一概不在数据里，不要假装知道
- 指数层依赖 `index_bars_daily`，它由 `/qk-stock-daily-update` 第 5 步维护；
  若指数段报不可用，先跑那个
- 用户只想看某一个维度（只问活跃市值/只看某个板块）时，别硬塞整份报告
