# 0AMV 活跃市值手工录入

指南针（compass.cn）专有虚拟品种，代码首字符是**数字 0** 不是字母 O。

`0号指数 = 0AMV + 0DMV`——0 号指数是沪深 A 股流通总市值，0AMV 是其中「活筹」（真正参与交易的活跃筹码）对应的市值，0DMV 是死筹市值。量纲是**市值**，不是成交额。

无官方 API、无第三方数据源。**但可以绕开界面直接从指南针本地数据文件批量提取**（见下「来源 B」），日常仍以人工录入为主。

> **量纲**：数值是市值量纲，当前量级在 **17 万上下**（2026-09 实测 172,364）。早期示例里写的 `52.88` 是错的，已删——如果用户报的数是两位数，先确认是不是换了单位（万亿 / 亿）。

## 存储

唯一真相源：`manual_data/0AMV.csv`（入 git，可人工改错）。

```csv
date,open,high,low,close,change_pct
2026-09-11,172625.6,174215.7,170860.4,172364.3,-1.30
```

`date` 为 `YYYY-MM-DD`；`change_pct` 单位是百分点（`1.09` 表示 +1.09%），留空则由脚本按前一条收盘自动推算。

不写入 `database/ashare_data.db`：该目录已被 gitignore，手打数据放进去等于无备份无历史。读取直接 `pd.read_csv()`，不走 `query_stock.py`。

## 运行

```bash
cd /Users/qianqian/stock/AshareLab
conda run --live-stream -n stock python .claude/skills/qk-stock-0amv/scripts/amv_store.py <子命令>
```

`--live-stream` 必需，否则 `conda run` 会缓冲输出到进程结束。

| 子命令 | 用途 |
|---|---|
| `add --json '<记录数组>'` | 录入，**默认仅预览不写盘** |
| `add --json - ` | 同上，JSON 从 stdin 读（数据量大时用） |
| `add ... --commit` | 确认后真正写入 |
| `add ... --commit --force` | 有疑点也强行写入 |
| `show [--tail N] [--json]` | 看已存数据 + 缺口检查 |
| `verify` | 全量重新校验 |

## 看状态（不是看数据）

用户问「活跃市值怎么样」「现在是什么区间」「能不能开仓」，答的是**择时状态**，不是数值 ——
用 `market/amv.py`，不要用 `show`：

```bash
conda run --live-stream -n stock python -m market.amv            # 最新
conda run --live-stream -n stock python -m market.amv 20260821   # 指定日期（回看）
```

输出形如「空头区间　距60线 -19.50%　60线斜率 -2.49%　MACD 水下死叉　→ 仓位上限 1~2 成」。

判据（区间划分、仓位上限出处）见 `market/amv.py` 模块 docstring。要点：

- **数字大小不重要，位置才重要**。孤零零一根 +4% 大阳线，若没站上 60 日线就是诱多
- 60 日线指**活跃市值自身**的，不是大盘的
- 空头区间 → 顶多 1~2 成仓；多头 + 当日 ≥4% → 可满仓（材料原文，别自己造阈值）

同一层也接在 `market.cli report` 的 L0 段和 `portfolio.monitor` 的市场层里。

## 工作流

**默认直接落盘，不要为了确认停下来。** 用户 2026-09-17 明确要求：只要脚本校验没有疑点，就直接 `--commit` 写入，然后在回复里报告写了什么（日期、四价、涨跌幅）。手打数据虽错一位就是脏数据，但脚本的校验已经覆盖了那些错法。

**但脚本报出疑点时必须停下来问。** 尤其是 3 倍检查（万亿/亿口径切换、多打一位数）和四价矛盾——脚本无从判断那是「数据源本来就这样」还是「抄错了」，只有用户能拍板。此时**不要 `--force` 绕过去**。

1. **解析用户输入**。形态不限——表格、截图、JSON、CSV、口述皆可，你负责归一成 `[{"date":..., "open":..., "high":..., "low":..., "close":..., "change_pct":...}]`。`change_pct` 可省。
   - 截图：读图取数，注意指南针数值栏的单位（万亿 / 亿），同一批数据单位必须一致。
   - 口述：「开 5.2 高 5.4 低 5.1 收 5.35」按 开/高/低/收 顺序取。
   - 日期省略年份时脚本按今年补，若落在未来则退一年。

2. **跑 `add`（不加 `--commit`）**，拿到预览与校验结果。

3. **看校验结果分两路**：
   - **无告警 → 直接加 `--commit` 落盘**，回复里报告写入的数值。
   - **有疑点 → 回显给用户并逐条说明**，不要替他判断。脚本会查：
     - 四价关系（`high` 必须最大、`low` 必须最小）
     - 涨跌幅与前收推算值是否吻合（容差 0.06 个百分点）
     - 相邻收盘价是否相差 3 倍以上（抓单位写错 / 多打一位数）
     - 是否周末、是否未来日期
     - 该日期是否已存在（存在则显示 `旧值 → 新值` 的 diff）
     若用户看了之后明确说数据没问题，加 `--force` 写入。

4. 落盘后可跑 `show` 复核，或提示用户 `git diff manual_data/0AMV.csv` 看变更。

## 来源 B：从指南针客户端直接提取（day.vdat）

指南针把行情写成本地二进制文件，0AMV 就在里面，可以绕开界面批量导出。参考实现：[`li-fujian/a-trend-data`](https://github.com/li-fujian/a-trend-data) 的 `scripts/extract_compass_amv.py`。

**文件路径**（Windows 默认安装）：

```
D:\Program Files\Compass\WavMain\ANALYSE\Data\ChinaStk\Z_SK\day.vdat
```

**解析要点**（自己写脚本时照这个来）：

- 按 ASCII 标记 `Z_SK0AMV` 定位数据段
- **28 字节定长记录**，`struct.unpack("<Iffffff", rec)` = uint32 日期 + 6 个 float（开 / 高 / 低 / 收 / 量 / 额）
- 日期是 `YYYYMMDD` 整数；须校验合法性、`close>0`、`open>0`、`high>=low`、`high/low` 与开收自洽
- 若按标记搜到多段，合并时日期必须严格递增，否则报错而不是静默拼接
- 与已知末根值交叉校验（差异 > 1.0 即退出），防止解析错位

**操作流程**（有硬约束，别跳）：

1. 打开指南针，**完成行情更新**
2. **彻底退出 `WavMain` 和全部 `ZnzBrowser`** —— 文件被占用会 `PermissionError`，此时要排查残留进程，**不要绕过文件锁**
3. 运行提取脚本，核对输出的末根日期

**当前状态**：用户是 macOS，这条路**尚未跑通**，后续可能在 Windows 上试。跑通后仍应把结果导入 `manual_data/0AMV.csv`（`add --json -` + `--commit`），**保持单一真相源不变**。

**已有引导数据**：`manual_data/0AMV_compass_raw.json` —— 1993-01-03 ~ 2026-09-11 共 8206 根，取自上述仓库的 `cache/compass/0AMV.json`，关键数值（2026-09-11 / 08-19 / 07-01）已经用户与客户端核对确认。格式为 `{symbol,name,source,source_code,kind,freq,last_updated,bar_count,bars[]}`，与 CSV 不同，导入前需转换。

## 来源 C：第三方仓库的现成数据（**仅在数据陈旧时用作参照**）

[`li-fujian/a-trend-data`](https://github.com/li-fujian/a-trend-data) 的
`cache/compass/0AMV.json` 有一份现成的 0AMV 日线（8206 根，1993 年起）。

```bash
curl -sL "https://raw.githubusercontent.com/li-fujian/a-trend-data/master/cache/compass/0AMV.json"
```

**这是别人的仓库，不是我们的依赖。** 它提交与否不受我们掌控，**不要写进任何日常
流程**（不接日更、不做定时抓取）。

**它的用途只有一个**：当我们自己的 `0AMV.csv` 有一段时间没更新，去看看它那边
是否也停滞了——如果它更新了而我们没有，说明是**我们的录入漏了**，把它上面的数据
同步下来补上即可。如果它也没更新，那大概率是上游（指南针客户端）那边的问题。

> 初次导入时核对过：关键点位与指南针客户端逐点比对一致（2026-09-11 / 08-19 /
> 07-01 三个锚点全对）。但**每次同步仍要回显给用户确认**，这是外部数据，
> 不能因为上次对就默认这次也对。

格式与 `manual_data/0AMV.csv` 不同（它是 `{symbol, name, bars:[{date,open,high,low,close,...}]}`），
导入前要用本技能第 1 步的 `add --json -` 转换，**不要直接覆盖 CSV**。

来源 B 与 C 的关系：B 是它的**方法**（读客户端 day.vdat），C 是它的**产物**（已导出的
JSON）。B 需要 Windows + 指南针客户端；C 只需要网络。两者都比手工录入省事，但都不该
取代 `0AMV.csv` 作为唯一真相源。

## 注意

- **预览不能跳，等确认可以跳**：每次都要先跑一遍不带 `--commit` 的 `add` 拿校验结果——无告警就直接续 `--commit`，只在有告警时回显给用户。跳过预览等于放弃脚本的四价 / 涨跌幅 / 倍数检查。
- **不要自己编 0AMV 数值**。缺数据就问用户，或让用户去客户端读；或按来源 B 从 `day.vdat` 提取。没有网络接口能拿到这个指标。
- 单位混用是最容易出的错。用户如果先报「52.31」后报「5231000」，八成是万亿与亿的口径切换，脚本的 3 倍检查会拦下来，此时应当追问而不是 `--force`。
- 数值本身是市值量纲。社区流传的通达信「高仿活筹指标」用的是两市成交额平滑，**与 0AMV 不等价**，不要拿来互相校验或补数。
