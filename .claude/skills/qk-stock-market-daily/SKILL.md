# 当日市场分析

把**客观数据**与**定性研判**合成一份「今天是什么环境、该做什么」的报告。

分两层，**不要混为一谈**：

- **客观层** —— `market.cli report` 的输出，各层的测量值与规则判定
- **研判层** —— 你把客观层综合成关键洞察。**这是本 skill 存在的理由**：客观层自己就能跑，缺的是「所以呢」

客观层有意不下结论。`market/analyze.py` 的 docstring 写着：「只做客观聚合与规则判定，
不下『主线就是 XX』的结论——那属于研究假设层，由人/AI 结合盘面与消息面研判。」
这句话划的就是本 skill 的职责边界。

## 运行环境（必读）

- conda `stock` 环境 + `PYTHONPATH=.` + `--live-stream`，三者缺一不可
  （缺 `--live-stream` 会缓冲输出到进程结束，看起来像卡死）
- 全部命令在项目根 `/Users/qianqian/stock/AshareLab` 下执行

## 步骤 1：确保当日快照存在

报告读的是 `market/history/YYYYMMDD.json`。先确认今天有没有：

```bash
ls market/history/$(date +%Y%m%d).json 2>/dev/null || echo "缺快照"
```

缺了就抓（约 30 秒）：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.cli snapshot
```

**快照必须当天抓。** 实时接口（乐咕活跃度、东财板块榜、同花顺/新浪行业）没有历史参数，
补抓会把今天的数据存成历史日期、污染环比。所以历史日期只能补到涨停池那几项，
`market.cli backfill` 就是干这个的——但补不出完整的当日快照。

## 步骤 2：跑报告

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.cli report
```

约 10 秒，输出八段：

| 段 | 内容 |
|---|---|
| **L0 活跃市值** | 区间、距 60 线、60 线斜率、MACD、**分级信号**（主题级/主线级/大牛市级）、**仓位上限** |
| **L0 指数** | 13 只（宽基 + 券商/银行两个信号指数）的当日涨跌、距各自 60 线、**两个风格轴**（大小盘 + 攻防）、**券商+沪深300+创业板共振** |
| **L0 阶段** | **当前该用哪套打法**（做突破 / 高抛低吸 / 左侧建仓），含滞后提示 |
| L1 情绪周期 | 五段状态机：涨停数/晋级率/炸板率/昨日涨停溢价 |
| L2 资金风向 | 沪深300 vs 中证2000 创 20 日新高占比、**期指基差**、**三只宽基 ETF 放量** |
| L2 风险信号 | 躲大跌清单：顶背离 / 平台破位 / 放量阴线 / MACD 金叉空 |
| L2 创新高板块 | **谁在突破**——创 20 日新高的股票按行业聚合 + 集中度 |
| L2 超跌板块 | KDJ 为负的行业，**按超卖深度排序** |
| L4 主线判定 | 有无主线、支线及所缺条件 |
| L3 连板梯队 | 5板/4板/3板/2板分布与封单 |
| L3 涨停行业分布 | 当日涨停的行业归属与前排个股 |
| L3 题材延续性 | 近 5 日进前 6 的次数 |
| L3 板块涨幅榜 | 概念 + 行业两套口径交叉验证 |

**L0 两段是前置闸门，其余是「参与什么」。** 读报告时先看 L0，它决定后面所有内容的
操作含义。

想单独看某一层，可以绕过报告直接跑：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.amv [YYYYMMDD]      # 活跃市值
PYTHONPATH=. conda run --live-stream -n stock python -m market.index [YYYYMMDD]    # 指数 + 共振
PYTHONPATH=. conda run --live-stream -n stock python -m market.sector [YYYYMMDD]   # 超跌板块
PYTHONPATH=. conda run --live-stream -n stock python -m market.table --days 30     # 每日观察数据表
```

`market.table` 是那张「每天维护的表」（`日期 / 活跃市值 / 涨停 / 沪深300创新高 / 中证2000创新高`），
用户要「看最近一段的走势对比」时直接给它。**它会自己标出「区间内哪些交易日没有快照」** ——
快照是手动触发的，缺的日子容易被误读成休市，补法是 `market.cli backfill --days N`。

### 几个必须转达的口径

- **ETF 日线可能滞后一天**（新浪该接口当天常还没出），输出里带 `⚠ 只到 YYYY-MM-DD` 要原样转达
- **期指基差跨换月日不能做环比** —— 当月合约交割日收敛到 0、换月后立刻转负是期限结构，
  实测 IF 从 -4.10 跳到 -36.73
- **超跌板块在普跌行情里没有区分度** —— 实测 2026-09-15 有 68/90 个行业 KDJ 为负，
  这时看排序（J 越负越超跌）而不是看是否在榜
- **中证2000 创新高的分母只有 699 而不是 2000**（库里缺北交所小票），是占比参照不是绝对家数

## 步骤 3：关键洞察（你做）

客观层给数据，这一层给判断。按五段组织：

### 一句话总览

今天是什么环境，一句话说清。例：「活跃市值空头 + 11 只宽基全在 60 日线下 + 情绪退潮
——三层同向，防守。」

### 层间一致性 / 矛盾

**这是关键洞察最重要的部分，也是只有你能给的部分。** 各层很少完全同向，
**矛盾处才是信息**：

- **指数横盘但活跃市值失血** → 钱在撤、价还撑着，最危险的一种。2026 年 8 月就是
  这个形态：上证微涨而 0AMV 跌 10.78%
- **活跃市值空头但情绪高涨** → 普跌里的局部抱团，参与要极轻
- **指数全部跌破 60 线 + 活跃市值空头 + 情绪退潮** → 三层同向，没有分歧，别找理由
- **活跃市值多头但指数在 60 线下** → 资金先动、价格没跟上，是观察窗口

### 三组核心数据的读法（措辞要按这个来）

这三组数据各有各的回答，**不要混着说**。

**① 活跃市值 = 增量资金**。涨幅直观看交投活跃度的提升与增量资金注入，涨幅高低还能
揭示资金流向与热点变化。分级措辞：

| 涨幅 | 写成 |
|---|---|
| **+4%** | 主题级——增量资金在炒主题 |
| **+8%** | 主线级——可炒主线 |
| **连续 +7~20%** | 十年一牛级别，可随意布局并长期持有 |
| **单日 -2.3% 以上** | 波段大概率结束，减仓或清仓 |
| **加速向下跳空** | 源系统视为见底信号（见下方实测注） |

> **关于「跳空见底」的实测**：用上证 8726 根日线检验，大涨跌日里跳空组的次日反弹
> 胜率 61.6%、普通大跌日 55.9%（211 样本）——**短期确有反弹倾向，但 3 日以上优势
> 消失、20 日胜率与普通大跌日持平**。而在**活跃市值**上跳空后是继续跌（跳空 >3% 时
> 20 日中位 -21%）。所以这条只对**价格指数**、且只在**短期**成立，别写成「见底」。

**② 涨停数量 = 市场赚钱效应**。**及格线随市况变化**：

| 市况 | 及格线 |
|---|---|
| 牛市 | 涨停 > **80** |
| 震荡市 | 涨停 > **60** |

低于及格线 → 赚钱效应差，短线需谨慎、空仓或轻仓。**但更关键的是曲线方向**——
涨停 93→73→48 是递减的，即便 48 本身不算低也要警惕。**看方向，不只看数值。**

**③ 两个「创 20 日新高」= 谁在动**。分口径是因为代表两类资金：

| 口径 | 代表 | 谁要重视 |
|---|---|---|
| 中证2000 | **游资** | 短线选手（衡量短线赚钱效应的关键指标之一） |
| 沪深300 | **机构** | **中长期投资者更要重视**——机构的运行情况决定市场中长期走势 |

创新高越多说明该类资金越积极。**对比看**：都高 = 全面进攻；一小一大 = 结构性行情；
都低 = 突破能力枯竭。

### 关键变化

与昨日 / 近 5 日比，**变了什么**。用数字不用形容词：
「60 线斜率由 -2.49% 转为 -3.06%，在下行加速」比「继续走弱」有用得多。

### 操作含义

- **仓位上限**（直接引用活跃市值层的判定，不要自己改）
- 能做什么 / 不能做什么
- 有持仓时，环境对持仓的含义

### 失效条件

什么情况下这个判断会变，**必须给出来**，否则判断无法被证伪。例：
「活跃市值站上自身 60 日线且 MACD 白线上水」。

## 步骤 4：落两份存档（文字版 + 图片版）

**两份内容不同，不要互相套用。**

| | 文字版 | 图片版 |
|---|---|---|
| 路径 | `market_reports/YYYY-MM-DD.md` | `market_reports/YYYY-MM-DD-image.md` + `.png` |
| 内容 | 完整数据 + 完整推理链 | 文字精炼 + **图表** |
| 图表 | 不带 | 必带（`charts/YYYY-MM-DD/`） |
| 用途 | 留档、细读、回查 | 分享、快速阅读 |
| **入 git** | **是** | **否** |

**只有文字版入 git。** 图片版与配图是派生产物——随时能从文字版与库里的数据重出，
而 PNG 体积不小（图版 1.8M/天 + 配图 0.6M/天）。`.gitignore` 已经挡住它们。

### 4a 文字版

按步骤 1-3 拿到的全部数据展开写：逐只指数、完整榜单、走势表、口径说明、
完整推理链，末尾附「原始数据出处」。**不加图表**——md 是拿来读源码的，图反而碍事。

### 4b 图片版

1. **先出图**：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.charts 20260915
```

   六张图落在 `market_reports/charts/YYYY-MM-DD/`：涨停家数折线、沪深300 创新高、
   中证2000 创新高、活跃市值 K 线、上证 K 线、上证 30 分钟 K 线+MACD。
   脚本自带 `assert` 校验落盘。

   单独看某一层（排查或按需取材）：

```bash
PYTHONPATH=. conda run --live-stream -n stock python -m market.stage  [YYYYMMDD]  # 阶段→打法
PYTHONPATH=. conda run --live-stream -n stock python -m market.risks  [YYYYMMDD]  # 风险信号
```

2. 读 `references/image_report_format.md`（**必读**，版面约束 + 九条硬规则 + 配图要求）
3. 按那份规范重写成图版 markdown，写到 `market_reports/YYYY-MM-DD-image.md`
4. 渲染：

```bash
PYTHONPATH=. conda run --live-stream -n stock python workflow/render_report.py \
    market_reports/2026-09-15-image.md --no-open
```

5. **渲染完自己 Read 一遍图** —— 这一步不能省。图片嵌入**会静默失败**（找不到图只
   print 一句警告，最终 PNG 里是坏图占位），项目里已经有一份报告这么坏掉且长期没人发现
6. 把 PNG 路径告诉用户

同一天重跑覆盖同名文件，所以「补充研判后重出图」是安全的。

### 4c 内容要求

**写完必须逐项勾选 `references/image_report_format.md` 里那张 10 项清单**——那是
唯一权威版本，不在这里抄第二遍（抄两处必然漂移，2026-09-16 就是因为要求只写在
一处、且是描述性措辞，导致图版把术语解释整节漏掉了）。

清单涵盖：六张图各就其位、术语解释独立成段、两个 20 日新高的含义与分母、宽基点评
而非罗列、上证形态独立成节、阶段那节说清打法、不引用出处、无 emoji 无横线。

其中**最容易漏的两项**单独提醒：

- **六张图必须都用上，且放到对应的那一节**。图存在不等于用对了——2026-09-16 那版
  把涨停折线放到了「操作含义」节，而讲「涨停 32→89」的情绪节反而没有图
- **术语解释对图版与文字版同等要求**。图版会独立传播，读者更需要它

**不引用规则出处**（文字版同样适用）—— 不写「《某某》说」「某某文档的判据」，
判断靠数据与推理自圆其说：

   ```
   ✗  依据是《十分钟讲透》里 2020-06-01 那个案例，文章判定信号无效
   ✓  若用大盘 60 线，那天上证已在自身 60 线上方，信号应当立即生效，
      但实际是又横盘许久才启动——只有用 0AMV 自身的 60 线才解释得通
   ```

   **成因**：这是给自己看的决策材料，规则从哪来不重要，「为什么在这里成立」才重要。
   （技能与规范文档不受此限——那是写给维护者看的。）

### 写图版时的四个高频错误

- **忘留空行** —— 标题、表格、列表、引用块前后各一个空行，否则会被 `<br>` 粘住
- **用了横向分割线** —— 不要写 `---`（模板里 `h1` 自带的那条 `border-bottom` 不算，
  那是标题下划线，去不掉也不用管）
- **把长数据挤一行** —— 12 只指数距 60 线必须拆成表格多行
- **上色用错类** —— 涨跌用 `.up` / `.down`（**红涨绿跌**）；`.positive` / `.negative`
  是语义上的「好/坏」，个股报告在用，别拿来当涨跌使唤

## 输出组织

```
一句话总览（环境定性 + 一句话依据）
        ↓
## 关键洞察        矛盾与一致、关键变化（研判，带数字）
        ↓
## 操作含义        仓位上限、能做什么不能做什么、对持仓的含义
        ↓
## 市场数据        客观层原文（L0 两段在前，L1-L4 随后）
        ↓
## 需人工确认      数据滞后、视野外的因素
```

**客观层原样引用，不要改写口径**；研判另起一段写明是你的判断。两者混成一句会让
用户分不清哪是测量、哪是推断。

## 纪律

- **不做收益预测**。可以说环境强弱、条件是否成立，不说「预计涨 X%」
- **层间矛盾必须摊开讲**，不要选一边悄悄忽略另一边
- **数据滞后要转达**：0AMV 靠手工录入，输出里的 `⚠ 0AMV 数据落后 N 个交易日` 原样带出来，
  并说明下面的判定基于落后数据
- **视野外的直说**：政策、消息面、减持解禁、外围市场一概不在数据里，不要假装知道
- 指数层依赖 `index_bars_daily`，它由 `/qk-stock-daily-update` 第 5 步维护；
  若指数段报不可用，先跑那个
- 用户只想看某一个维度（只问活跃市值/只看某个板块）时，别硬塞整份报告
