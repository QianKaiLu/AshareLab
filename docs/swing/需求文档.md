# 波段持仓监控与复盘 — 需求文档

> 状态：v0.4，设计定稿，可进入实现
> 日期：2026-09-05
> 定位：交易系统中「波段操作」分支（区别于「长期价值投资」）的核心日常流程。

---

## 0. 一句话目标

把「波段持仓的日常监控 + 买卖点复盘」沉淀成 **工具（py 脚本）+ AI skill** 的组合：

- **交易记录 + 便签 + 止损计划** 长期结构化存储（JSONL 入 git），可复盘、可归档；
- **AI 每日分析** 持仓形势，结合 B1 / 双线 / BBI / MACD / KDJ / 出货识别等交易系统规则；
- **脚本只测客观数据，AI 做定性判断** —— 不追求死板的指标结论，充分利用 AI 结合交易系统、便签历史、盘面细节做综合研判。

## 3. 核心数据

### 3.1 目录结构（JSONL 追加式，入 git）

```
portfolio/
  swing/                       # 波段账户（未来 value/ 长期账户并列）
    trades.jsonl               # 逐笔交易
    notes.jsonl                # 便签
    stops.jsonl                # 止损计划及其调整（追加留痕，D9）
    daily/YYYY-MM-DD.md        # 每日监控存档（D6）
    closed/<code>.md           # 清仓归档
```

### 3.2 交易记录（Trade）

`{id, code, name, side(buy/sell), date, price, qty, note_id?, remark?, snapshot{}}`

- 买入 `side=buy`，卖出 `side=sell`；加仓 = 再来一条 buy；部分卖出 = sell 且 qty < 持仓。
- 不含 `fee`（D15）。
- `snapshot`（D14）：成交日的客观测量值，落盘时算一次存死。至少包含 `kdj_j`、`kdj_j_weekly`、`z_white`、`z_yellow`、`bbi`、`macd_state`、`vol_ratio`、`pos_in_breakout_range`、`b1_variant`。
- 持仓与成本从 `trades.jsonl` **现算不另存**（避免两份真相），按 D3 加权平均。
- 清仓（持仓归零）→ 归档该票全部 trades + notes + stops 到 `closed/<code>.md`。

### 3.3 止损计划（Stop，D9）

`{id, code, date, plan, price?, basis?, related_trade_id?}`

- `plan` **必填**，文字描述，例：「跌破黄线 11.45 且次日无法收回则离场」「守 8-24 那根低点 12.32」。
- `price` / `basis`（黄线 / 白线 / 点火低点 / N 型低点 / 人工指定）**可选** —— 有明确价位就填，方便日报机械对照。
- 调整止损 = **追加一条新记录**，不改旧的。这样能统计「往下挪止损」的次数，那是自欺的可靠探针。
- 买入时应同时写一条 Stop（核心原则：每一笔交易都必须有止损计划），但不强制阻塞录入。

### 3.4 便签（Note）

`{id, date, code?, type, text, related_trade_id?, status?, due?}`

- `type`：买入理由 / 卖出理由 / 盘中异动 / 交易计划 / 复盘结论…
- 绑定：可绑某笔操作（`related_trade_id`），也可只绑某天（`date`），两者并存。
- `status`：待验证 / 已验证 / 已复盘；`due`：到期日（D5）。

## 4. 两大 AI 分析场景

### 场景 A：买入后买点复盘

**触发**：录入一笔买入后，或「复盘一下 XX 的买点」。

**流程**：脚本测客观值（复用 `b1_review.py`，基于黄白线）→ AI 结合 B1 规则 + **实际买入价 vs 理想买点价偏离度** + **便签里的买入理由** 做定性判断。

**输出**：买点归类（完美一/二/三/四，或「不构成 B1」）+ 偏离度 + 止损建议 + 后续跟踪要点。

**与 `qk-stock-b1-review` 的区别**：那是「这张图是不是好 B1」的静态体检；这里多了成本、买入理由、事后走势对照。

**诚实前提（D8）**：本场景是**事后复盘**，不满足核心原则第二条的「事前依据」。它的价值在于积累「我的买点质量分布」，而非为已成交的交易背书。AI 不应把事后测量说成买入时的依据。

### 场景 B：每日持仓监控

**前置**：先跑 `qk-stock-daily-update`（当天已更可跳过）。

**输出组织（D11）**：按行动重要性，不按股票罗列。

```
1. 需操作（止损触及 / 离场信号 / 减仓信号）—— 展开细节
2. 需观察（接近止损 / 信号临界 / 便签到期待验证）—— 展开细节
3. 无事持有 —— 每票一行带过
```

**每票细节包含**：

- **跟踪对照放第一行** —— 我上次写的判断是什么，今天走势应验还是证伪（这是本流程的核心价值，指标随时能算，判断对照只有存了便签才有）
- 当前位置：现价 vs 白线/黄线/BBI；日线 J + **周线 J**（D16）；MACD 三层（0 轴上下、金叉死叉、柱收扩）
- 止损：对照 `stops.jsonl` 里**我当初写下的计划**，是否触及
- 卖点：BBI 连续两日收盘跌破（清仓）、BBI 上两根中大阳（减仓）、出货 S1~S5、顶背离后反拉
- 异动：放量异动、连续堆量、KDJ 背离、V 型反转

**结尾**：「今日需人工确认」清单；结果按天存档（D6）。

## 5. 落地方案

### 5.1 skill 划分（D13）

取消总入口，三个平级 skill，共享一个 py 包：

```
.claude/skills/
  qk-stock-swing-trade/     # 记一笔（买卖 + 挂便签 + 写止损计划）
  qk-stock-swing-daily/     # 每日持仓日报（场景 B）
  qk-stock-swing-review/    # 单票买点/卖点深度复盘（场景 A）

portfolio/                  # 共享 py 包（不放进某个 skill 的 scripts/）
  __init__.py
  store.py                  # JSONL 读写
  position.py               # 持仓/加权成本/盈亏现算
  snapshot.py               # 测量快照采集（D14）
  cli.py                    # 命令行入口
```

py 包放仓库根的 `portfolio/`，三个 skill 都 import 它 —— 一套工具统一管理，不在 skill 之间复制脚本。

### 5.2 分工原则（继承 b1-review 的成功范式）

- **脚本**：只算客观测量值，输出结构化 JSON。
- **SKILL.md**：工作流 + 评价体系 + 阈值基准 + 输出格式。
- **references/**：交易系统规则摘录。
- **AI**：综合研判、结合便签历史、给出操作建议与失效条件，显式引用证据（日期+数值）。

### 5.3 每日串联

```
/qk-stock-daily-update            # 更新行情（前置）
        ↓
/qk-stock-swing-trade 记一笔       # 有操作时
        ↓
/qk-stock-swing-daily 持仓日报     # 场景 B
        ↓
/qk-stock-b1-daily                # 背景：今天有没有新 B1 机会（可选）
```

## 6. 落地顺序

每步完成后验收，再进下一步。

1. **存储层**：`portfolio/` py 包 —— JSONL 读写、交易增删、加权成本/持仓/盈亏、便签、止损、清仓归档 + CLI。验收标准：能手动录一条买入、查持仓、算成本。
2. **周线 KDJ 指标**（D16）：日线重采样成周线算 KDJ，`indicators/` 下按现有 `add_*_to_dataframe` 范式实现。
3. **测量快照**（D14）：`snapshot.py` 采集，接到交易录入流程里。
4. **每日日报 skill**：`qk-stock-swing-daily` —— 脚本测值 + SKILL.md 评价体系，按 D11 组织输出。
5. **单票复盘 skill**：`qk-stock-swing-review` —— 场景 A，复用 `b1_review.py` 叠加成本与理由。
6. **记账 skill**：`qk-stock-swing-trade` —— 自然语言解析。**放最后**：初期直接调 CLI 录入即可，自然语言是体验优化不是前提。

顺序理由：先做存储 + 日报，因为日报是每天真正会用的东西，也是唯一能验证数据模型够不够用的方式。
