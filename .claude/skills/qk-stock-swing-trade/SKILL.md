# 记一笔交易

把口语化的成交描述转成结构化记录。你负责解析与确认，落盘交给 CLI。

## 运行环境

```bash
cd /Users/qianqian/stock/AshareLab
conda run --live-stream -n stock python -m portfolio.cli <子命令>
```

`--live-stream` 必需，否则 `conda run` 缓冲输出到进程结束。

所有写入命令**默认只预览**，加 `--commit` 才落盘。这是有意的：解析口语容易出错，先让用户看一眼再落。

## 子命令速查

| 命令 | 用途 |
|---|---|
| `buy <股票> <价格> <数量> [日期]` | 录入买入 |
| `sell <股票> <价格> <数量> [日期]` | 录入卖出，清仓时自动归档 |
| `note <股票\|market> "内容"` | 挂便签 |
| `stop <股票> "计划"` | 写/改止损计划（追加留痕） |
| `verify <便签id> "结论"` | 给便签盖章 |
| `show` / `detail <股票>` / `pending` | 查持仓 / 单票明细 / 未验证便签 |
| `archive [股票]` | 生成清仓归档 |
| `rm <记录id>` | 删除一条记录 |

## 解析规则

### 必需三要素

**价格、数量、方向**缺一不可。日期缺省按今天，但用户说「昨天」「上周五」要换算成实际日期（`--date` 接受 `20260904` / `2026-09-04` / `9-4`）。

数量口语：「一千股」= 1000，「两手」= 200，「1万股」= 10000。A 股按手成交，数量应是 100 的整数倍 —— 不是的话提一句但不阻塞（可能是可转债或科创板）。

股票可以给名称或代码，CLI 会模糊匹配并回显匹配到的名字 —— **让用户看到这个回显**，名称匹配可能匹错。

### 买入必问止损

核心原则：每一笔交易都必须有止损计划。用户没提就问一句，不要静默录入。

止损计划的三种形态，都合法：

```bash
# 有明确价位 + 依据线
--stop "跌破黄线11.16且次日不收回则离场" --stop-price 11.16 --basis 黄线
# 只有文字计划（价位不好客观确定，如 N 型上一低点）
--stop "守 8-24 那根阴线的低点，收盘破了就走"
# 用户明确表示暂不设（少见，要如实记下）
--stop "暂未确定，明日看盘后补"
```

`--basis` 可选值：`黄线` / `白线` / `点火低点` / `N型低点` / `BBI` / `人工`。

用户说不出止损位时，可以给建议 —— 跑 `/qk-stock-b1-review <代码>` 拿脚本算出的黄线、白线、点火首日低点，**但最终由用户定**，别替他决定。

### 买入理由记成便签

`--reason` 存为「买入理由」便签，`status=待验证`。这是日后复盘的唯一事前证据，值得多问一句「为什么现在买」。

`--due` 设复盘到期日。没说就按洗盘预期给：前期涨幅低的票 5~8 个交易日，涨幅高的 10 天以上（洗盘时长与前期涨幅正相关）。

### 卖出问理由

`--reason` 存为「卖出理由」便签。卖出理由比买入理由更容易事后失真，当场记下来。

清仓（持仓归零）时 CLI 会**自动归档**到 `portfolio/swing/closed/<code>.md`，并提示还有哪些便签待验证 —— 清仓正是回看判断的时机，顺手用 `verify` 盖章。

## 确认流程

1. 先跑不带 `--commit` 的预览
2. 把关键字段念给用户：股票名（CLI 回显的）、方向、价格、数量、日期、止损计划
3. 买入还要念快照给出的两个偏离度 —— **买入价 vs 当日收盘**（B1 是收盘信号，追高多少直接吃掉容错空间）和**距止损位百分比**（这是单笔最大风险敞口）
4. 用户确认后加 `--commit` 重跑

改止损时 CLI 会检查是否下移，下移会警告「这通常是自欺的信号」—— **把这句话如实转达**，不要因为用户可能不爱听就省略。

## 便签验证

```bash
... -m portfolio.cli verify N20260825-300314-1 "黄线11.16未破，判断成立；但没料到会连续6日收白线下" --commit
```

原判断保留不变，结论附加在 `result` 字段。`--status` 可选 `已验证`（默认）/ `已复盘`。

盖章要写**应验或证伪的具体依据**，不要只写「对了」「错了」—— 复盘的价值在于知道当时哪一步想对了、哪一步没想到。

## 边界

- **交易记录不能改**，只能删除重录（`rm <id> --commit`）。改了会让持仓与历史对不上
- **止损不能改**，只能追加新记录。改了会抹掉「当时写的是什么」，而那正是纪律的痕迹
- 便签可以用 `verify` 盖章，正文本身不改
- 卖出数量超过持仓不报错，按可卖数量计并记 warning（可能是补录历史）
- **不含手续费**（设计决策 D15），盈亏是毛额

## 顺带一提

录完买入后可以问用户要不要跑 `/qk-stock-swing-review` 复盘买点质量，或跑 `/qk-stock-swing-daily` 看整体持仓形势。别自动跑，问一句。
