# 市场日报图版：排版规范

写给 AI 看的。图版报告由**重写**产生（不是截取终端报告的字符串），这份文档规定重写成什么样。

## 为什么必须重写，不能直接渲染

`market/analyze.py:render()` 的输出是逐行 `append` 再 `"\n".join()` 的紧凑文本，
行与行之间**没有空行**。而渲染器（`tools/markdown_lab.py`）开着 `nl2br` 扩展——
单换行会变成 `<br>`。

**实测**（2026-09-15）：

```
输入：  ## L0 活跃市值：**空头**
        活跃市值 166,792（09-15）
        走势：09-14 -1.42　09-15 -1.83

输出：  <h2>L0 活跃市值：<strong>空头</strong></h2>
        <p>活跃市值 166,792（09-15）<br />
        走势：09-14 -1.42　09-15 -1.83</p>     ← 两行被粘进同一个 <p>
```

结果是一块没有呼吸感的文字墙。**所以「AI 转换格式」这一步不是走形式，是必需的** ——
数据用同一份，排版重来。

（`>` 引用块实测不受影响，能正常起块。这个问题只出在普通段落的换行上。）

## 版面约束（实测值，改之前先读）

| 项 | 值 | 来源 |
|---|---|---|
| 输出图宽度 | **1200 px** | Playwright viewport 600 × device_scale_factor 2 |
| 实际内容宽度 | **560 CSS px** | 600 减去 body 的 `padding: 20px` 左右共 40 |
| 模板的 `max-width: 680px` | **不起作用** | viewport 只有 600，body 先被卡住了 |

560px 的含义：**表格最多 4 列**，每列净可用不到 100px，中文标签超过 6-7 字就折行。

## 结构

```
# 市场环境日报　2026-09-15

**环境定性一句话**（空头区间 · 仓位上限 1~2 成 · 三层同向）

---

## 一、市场闸门

（活跃市值 + 指数两张小表，末尾一条引用块小结）

---

## 二、情绪与资金

## 三、热点结构

## 四、关键洞察

## 五、操作含义与失效条件
```

章节序号用中文数字（一、二、三）。`---` 分隔每个 `##` 章节。

## 硬性规则

每条都附了成因——**成因不成立时规则才可以改**，不要当成教条照搬也不要随手删。

### 1. 标题、表格、列表、引用块的前后各留一个空行

**成因**：`nl2br` 会把单换行变成 `<br>`，不留空行的话相邻两行会粘进同一个 `<p>`
（见上面的实测）。`markdown_lab.py:preprocess_markdown()` 只对「`**加粗行**` 或
`##标题` 紧跟列表」这一种情况自动补空行，其余一概不管。

### 2. 表格不超过 4 列

**成因**：内容区 560px。5 列时每列约 90px，中文标签会折成两行，反而更难读。

### 3. 长数据拆成多行表格，不要挤在一行

12 只指数距 60 线的正确写法：

```markdown
| 指数 | 距60线 | 当日 |
|---|---:|---:|
| 上证 | -1.75% | -0.54% |
| 上证50 | -2.72% | -0.52% |
```

错误写法：`距60线（由近到远）：上证 -1.75%　上证50 -2.72%　…（12 个挤一行）`。
**成因**：560px 放不下，会折成 4 行且难以对齐，表格才读得出来。

### 4. 涨跌数字上色

模板里已有两个类，直接用：

```html
<span class="positive">+1.55%</span>      <!-- 橄榄绿 -->
<span class="negative">-1.83%</span>      <!-- 陶土红 -->
```

**成因**：`md_in_html` 扩展开着，原始 HTML 会透传；`.positive` / `.negative` 是
`markdown_lab.py` 模板里既有的类，**不需要改 CSS**。涨跌数字满屏都是，
上色后扫读速度快很多。

只给**数字**上色，不要整行加粗变色。

### 5. 不使用 emoji

**成因**：这是每天的决策材料，不是营销图。用户明确要求严肃。h1 也不带。

（个股分析报告的 h1 带过一个 📊，那是模型自加的，提示词里并没有要求——市场版不要继承。）

### 6. 每章结尾一条 `>` 引用块作小结

**成因**：沿用个股报告的视觉签名。读者对「每章末尾有一句人话结论」形成预期后，
可以只扫引用块快速过一遍。

引用块内容用**口语化的一句话**，不要复述上面的数字。

### 7. 章节顺序：闸门优先

市场闸门（活跃市值 + 指数）必须在最前。

**成因**：它回答「要不要参与」，其余章节回答「参与什么」。空头区间下后面的信号再多
也要降档读。`market/analyze.py:410` 的注释写的就是这条。

### 8. 闸门缺数据必须显式写出，不得省略该章

即使 0AMV 数据缺失，也要保留「一、市场闸门」这一章，写明：

```markdown
> 活跃市值数据不可用（manual_data/0AMV.csv 无 09-15 之前的数据），本节无法判定。
```

**成因**：`analyze.py:414` 的纪律——「闸门缺数据不能静默消失，『没看到警告』会被误读成
『可以参与』」。这与个股报告「没新闻就略过第 2 章」的做法**相反**，别照搬那边。

## 不沿用的两处

| 个股报告有 | 图版市场报告 | 理由 |
|---|---|---|
| h1 带 emoji | 不带 | 用户要求严肃 |
| 结尾免责声明 + 出品方 | 不写 | 那是给外部读者的；这是个人复盘材料 |

## 写完自检

1. 全文搜一遍，确认零 emoji
2. 每张表数一遍列数，≤4
3. 每个 `##`、表格、列表、`>` 前后都有空行
4. 涨跌数字都包了 `<span class="...">`
5. 每个 `##` 章节末尾都有 `>`
6. 闸门章节在第一节，且没有被省略
